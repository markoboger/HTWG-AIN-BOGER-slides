# Your Role as a Tutor

- You **assess** submissions: play, read, and check them against the task.
- You **give feedback** that helps students improve, not only a grade.
- You grade **consistently**: same task, same criteria, for every student.
- You **escalate** unclear cases (suspected copying, missing files, disputes) to us instead of deciding alone.

# Assessing a Scratch Project

<div style="font-size: 18px;">

| Criterion | What to check |
|---|---|
| **It works** | Play it: green flag starts cleanly, controls respond, scoring counts, game over or goal is reached. Start it twice: are all values reset? |
| **Appropriate blocks** | Fitting blocks for the job (e.g. `forever` + `if` instead of copy-pasted steps, `broadcast` instead of timing tricks). |
| **Readable scripts** | Meaningful sprite and variable names, custom blocks for repeated parts, no duplicated code, scripts tidy. |
| **Lecture concepts used** | 01: events, variables, expressions, messages. 02: clones, lists, custom blocks, game states. |
| **Versioning** | Several meaningful commits with clear messages, not one upload at the end. |

</div>

---

# Checklists for the Scratch Tasks

<div class="columns" style="font-size: 17px; gap: 1.6rem; align-items: start;">
<div>

**Lecture 01 Task:** expressions, variables, messages

<strong style="color: #575e75;">Must have</strong>

- a variable that is **set, changed and read** (condition or monitor)
- real expressions: operators, comparisons, `pick random`
- `broadcast` + `when I receive` between sprites

<strong style="color: #575e75;">Common mistakes</strong>

- variable created but never used
- message sent, but no one receives it
- start values not reset on green flag

Reference: `assets/Scratch/Pong.sb3`

</div>
<div>

**Lecture 02 Task:** clones, list, custom blocks, game states

<strong style="color: #575e75;">Must have</strong>

- clones created **and deleted** again
- a list actually used (add, item, length), cleared at start
- custom blocks with a clear purpose; explicit game state
- one debugging strategy; student can explain concurrency

<strong style="color: #575e75;">Common mistakes</strong>

- clones pile up and slow the game down
- "for all sprites" vs. "for this sprite only" mixed up

Reference: `assets/Scratch/Snake.sb3` (clones + two lists; no state variable)

</div>

# Giving Feedback

<div style="font-size: 21px;">

- **Start with what works.** Name one thing the student did well.
- **Be specific.** Point to the sprite, script, or line: "In *Ball*, the second `forever` loop …"
- **Prioritize.** The one to three most important points, not everything.
- **Explain why, hint how.** Give a direction, not the finished solution.
- **Stay consistent and friendly.** Same criteria for everyone; criticize the code, not the person.
